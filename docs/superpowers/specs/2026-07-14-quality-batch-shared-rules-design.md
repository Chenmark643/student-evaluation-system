# 素拓批量加分共用项目与上限规则设计

## 目标

批量加分与单人加分使用同一套项目库、加分类别、等级、默认分数和上限规则。用户在批量区选择预制项目后即可自动带出完整信息，也可以继续输入自定义项目并手动调整字段。

## 方案选择

采用“共享数据源与初始化流程”，不复制一套独立规则，也不把批量操作强制放进材料审核抽屉。

- 推荐方案：批量表单复用单人录入的数据源和联动逻辑。改动集中、操作直接，后续新增项目或类别会自动同步。
- 备选方案一：为批量表单复制一套加载逻辑。短期简单，但以后项目和上限容易再次不一致。
- 备选方案二：批量操作也打开材料审核抽屉。复用最彻底，但批量选人和项目设置会被拆成两个页面，效率较低。

## 交互设计

1. 导入花名册后，批量区同时加载：
   - 完整预制与自定义项目列表；
   - 完整加分类别列表；
   - 当前全部上限规则。
2. 选择已有项目时，自动带出类别、等级和默认分数。
3. 修改类别时，等级列表按该类别刷新；用户可以继续修改等级和分数。
4. 表单下方显示当前项目命中的规则：
   - 求和封顶：显示“本组累计最高 X 分”；
   - 取最高：显示“本组多项只取最高，最高 X 分”；
   - 未命中规则：显示“该类别暂无上限”。
5. 预览逐人显示添加后的有效总分、是否触及上限以及具体规则。
6. 执行批量添加时保存原始加分明细；最终计算与导出仍由统一上限算法完成。

## 数据与边界

- 项目、类别和上限只从现有后端接口及 `qualityThresholds` 读取，不增加第二份配置。
- 批量初始化在页面首次显示、花名册导入完成及类别/上限编辑关闭后刷新。
- 自定义项目允许使用任意已有类别；新类别仍通过现有“管理加分类别”入口创建。
- 重复判断保持现有规则：项目、类别、等级、分数完全相同时跳过。
- 班委测评与组织测评继续归入同一 `max_item` 组，只取最高。

## 错误处理

- 项目库或类别接口读取失败时使用页面已有数据，不让批量区变成不可操作状态。
- 没有项目名称、类别或有效分数时禁止预览和执行，并给出明确提示。
- 规则未命中不视为错误，只提示“暂无上限”。

## 验证

- 前端契约测试：批量初始化必须加载项目、类别和上限提示。
- 联动测试：项目选择能填充类别、等级和分数。
- 规则测试：求和封顶与 `max_item` 在批量预览中使用现有统一算法。
- 回归测试：单人加分、材料抽屉、批量去重及 Excel 合并导出保持正常。
